## 📖 這份檔案怎麼用

0. **先選版本和風格**：個人／情侶出遊用輕量版（`spec-lite.md`）；團體用這份；領隊帶團再加 `spec-leader.md`。風格 6 選 1，見 `styles.md`
1. **填寫第三部分「你的旅程資料」**：把 `【】` 裡的內容換成你自己的，不需要的區塊可以整段刪掉
2. **把整份檔案交給 AI 寫程式工具**（例如 Claude Code），並貼上這段指令：

   > 請依照這份規格書，幫我做一個團體旅遊手冊網頁，內容用第三部分我填寫的資料。
   > 先輸出簡要計畫讓我確認，再開始做。部署方式照第五部分。

3. **先看第零部分「開始前準備」**：準備好帳號和軟體，並了解過程中會跳出哪些授權畫面（約 10 分鐘）
4. **跟著第五部分「上線步驟」**讓 AI 幫你上傳；需要你親自按的授權，AI 會停下來請你操作
5. **拿到網址丟到群組**，請大家「加到手機主畫面」，旅途中隨時打開
6. **卡住了**：先查第九部分「錯誤訊息對照表」

💰 **全部免費**：網站放在 Cloudflare 免費方案，不需要買網域、不需要伺服器、不用綁信用卡。

# 第一部分：成品長什麼樣子

一個**手機優先**的網頁，底部有 8 個分頁按鈕，旅途中單手就能操作：

| 分頁 | 一句話說明 |
|---|---|
| 🏠 首頁 | 出發倒數／今天是第幾天、下一個集合時間（大字倒數）、天氣、今日穿搭、航班、保險 |
| 🗓️ 行程 | 每天的時間軸，點開看交通方式、地圖、注意事項，每段都能記帳 |
| 💰 花費 | 全團共用帳本、自動分帳、誰該轉給誰多少、公積金帳本 |
| 🏨 住宿 | 每一間住宿的地址（含當地語言給司機看）、入住規定、聯絡電話、**分房清單** |
| ☎️ 聯絡 | 團內聯絡人、包車司機、當地緊急電話，一鍵撥號 |
| ✅ 清單 | 出發前準備（簽證／入境申報步驟卡）、打包清單（每人自己打勾）、預約確認、匯率換算、實用外語（可點播發音） |
| 🎁 推薦 | 拍影片範本、景點攻略、伴手禮／美食／按摩推薦（**大家都能新增、按讚**） |
| 💬 留言 | 免登入留言板 |

**最重要的設計原則**：
- **打開就知道現在要做什麼**：網頁會依當地時間自動判斷今天第幾天、下一次集合在哪
- **不用登入**：拿到網址就能看、能記帳、能新增推薦
- **一份資料、大家同步**：記帳、分房、推薦、留言存在雲端，全團看到同一份
- **不會因為改行程打亂資料**：每段行程有固定編號，插入新行程不影響已記的帳

# 第二部分：功能規格（給 AI 看的）

## 2-1 技術架構

| 項目 | 做法 |
|---|---|
| 網頁本體 | **單一 `index.html`**（HTML＋CSS＋原生 JavaScript，不用框架）。**以 `assets/group/index.html` 為底**，所有旅程資料集中在 `<script>` 開頭的設定區，換旅程只改設定區 |
| 風格 | `assets/themes/themes.css` 的 6 種風格，`index.html` 開頭 `THEME` 選一種；改了 themes.css 要跑 `node tools/sync-themes.mjs` 同步 |
| 示範模式 | 網址加 `?demo`（或放在 github.io、直接開檔案）時，用設定區的 `DEMO_SEED` 假資料，**不讀寫雲端**，方便預覽和測試 |
| 放置位置 | **Cloudflare Pages**（免費），網址像 `xxx-隨機碼.pages.dev` |
| 共用資料 | **Cloudflare D1**（免費 SQLite 資料庫）＋ **Pages Functions**（`functions/api/*.js`） |
| 天氣 | **Open-Meteo**（免費、免註冊、免金鑰），前端直接呼叫 |
| 外語發音 | 瀏覽器內建語音朗讀（`speechSynthesis`，語言寫在 `TRIP.lang`，例如 `ja-JP`、`th-TH`），不用錄音檔，Mac／Windows／手機都能用 |
| 影片 | Instagram 官方內嵌 `https://www.instagram.com/reel/<ID>/embed/`（iframe） |
| 個人狀態 | `localStorage`（打包清單勾選、♡ 我的清單、展開狀態、暱稱）— **一律包 try/catch** |
| 部署 | `wrangler pages deploy`，用 `deploy.sh` 一鍵上傳 |

**資料夾結構**
```
專案/
├── site/
│   ├── index.html        # 網頁本體（所有設定都集中在 <script> 開頭的常數）
│   ├── _headers          # X-Robots-Tag: noindex, nofollow
│   ├── robots.txt        # Disallow: /
│   └── img/              # （選填）說明圖片，例如機場接機位置圖
├── functions/api/
│   ├── messages.js       # 留言板
│   ├── expenses.js       # 記帳
│   ├── recs.js           # 推薦（伴手禮、美食、按摩…）
│   ├── likes.js          # 推薦按讚
│   └── rooms.js          # 分房
├── wrangler.toml         # Pages 設定 + D1 綁定
├── deploy.sh             # 一鍵部署
└── admin.key             # 留言板管理密碼（加入 .gitignore，不上傳）
```

## 2-2 資料庫（D1）

```sql
CREATE TABLE messages (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, body TEXT NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE expenses (id INTEGER PRIMARY KEY AUTOINCREMENT, day INTEGER NOT NULL, item INTEGER NOT NULL, title TEXT NOT NULL, amount REAL NOT NULL, currency TEXT NOT NULL, payer TEXT NOT NULL, split TEXT NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE recs (id INTEGER PRIMARY KEY AUTOINCREMENT, cat TEXT NOT NULL, name TEXT NOT NULL, en TEXT, why TEXT, warn TEXT, shops TEXT NOT NULL, place TEXT, author TEXT NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE rec_likes (rec_id INTEGER NOT NULL, voter TEXT NOT NULL, created_at INTEGER NOT NULL, PRIMARY KEY (rec_id, voter));
CREATE TABLE room_assign (name TEXT PRIMARY KEY, room INTEGER NOT NULL, updated_at INTEGER NOT NULL);
CREATE TABLE settle_paid (name TEXT PRIMARY KEY, amount INTEGER NOT NULL, dir TEXT NOT NULL, paid_at INTEGER NOT NULL);
```

## 2-3 API（Pages Functions）

| 路徑 | 方法 | 說明 |
|---|---|---|
| `/api/messages` | GET / POST / DELETE | DELETE 需 header `X-Admin-Key`（伺服器 secret `ADMIN_KEY`）；POST 有隱藏欄位防機器人 |
| `/api/expenses` | GET / POST / PUT / DELETE | 驗證：金額 > 0、付款人、分帳的人必填；幣別只收本國幣／當地幣 |
| `/api/recs` | GET / POST / PUT / DELETE | GET 帶 `?voter=` 一併回傳讚數與「這支手機按過沒」；分類白名單 |
| `/api/likes` | POST | 同一個 voter 對同一推薦：按一次加讚、再按收回 |
| `/api/rooms` | GET / POST | POST `{room, names}` 設定某房成員；一人只會在一間房（自動從原房移出） |
| `/api/settle` | GET / POST | 結算確認：POST `{name, amount, dir:"pay"|"refund", paid:true/false}`，勾選／取消；任何人可操作 |

**安全原則**：所有使用者輸入在畫面上都要跳脫（escape），避免有人貼程式碼破壞網頁；文字長度都要設上限。

## 2-4 時間邏輯（最核心）

- 全站用**目的地當地時間**計算（例如曼谷 UTC+7），頁首同時顯示「當地時間（台灣時間）」
- 網址加 `?now=2026-10-08T14:40` 可以**模擬任何時間**，用來測試
- 出發前：首頁顯示倒數天數、入境卡開放倒數
- 旅途中：自動跳到「今天」、正在進行的行程標「進行中」並自動展開
- **下一個集合**：
  - 找下一個 `meet: true` 的行程，大字顯示時間＋剩餘分鐘＋地點＋地圖按鈕
  - **分組行動的日子**：每一組各顯示自己的下一個集合，再加一張「下一次全員集合」
- 旅程結束後：顯示「旅程結束 🎉」

## 2-5 各分頁規格

### 🏠 首頁
0. 主視覺：手繪 SVG 插圖（題材配合目的地）＋旅程名稱＋日期＋亮點數字（例：6 天／4 座城市／2 晚溫泉）
1. 狀態卡（倒數＋旅程簡介／Day X＋當天標題＋現在進行中）
2. 天氣卡（當天）／出發前顯示整趟 N 天天氣條
3. 今日 Dress Code（有設定才顯示）
4. ⏰ 下一個集合（可能多張，分組時）
5. 今天的行程（分組日自動分區）
6. ✈️ 航班卡（像登機證：出發／抵達機場代碼、時間、標註哪國時間、機型、飛行時間、托運額度）＋報到提醒＋「查行李轉盤」按鈕（例：桃園機場 `https://www.taoyuan-airport.com/flight_arrival?k=<航班號>&time=all`，打開直接顯示該航班）
7. 📝 個別提醒（例如某人要帶的證明文件）
8. 🧳 托運行李（哪些人有買托運、去回程件數）
9. 🛡️ 旅遊保險（保額表＋24 小時急難救助電話一鍵撥號＋理賠要準備什麼，可收合）
10. 📲 加到手機桌面教學

### 🗓️ 行程
- 上方：天數切換按鈕（選中的自動捲到看得到的位置）
- 天氣卡（該天地點的預報，可依天數設定不同城市）
- 當天標題（一句有畫面的標題，例：「Day 2・運河與玻璃的港町」）、交通／住宿摘要、今日 Dress Code
- 分類篩選（景點／用餐／購物／交通／住宿），每段行程可加交通彩色小標籤（`tags`）與「必去」（`must`）
- 切換日期時內容輕輕彈一下；最下方「旅人提醒」框＋前一天／下一天按鈕
- **時間軸**：每段行程是可展開的卡片
  - 摺起來：時間、標題、標籤（集合／進行中／分組／💰 已記金額）
  - 展開：👥 分組成員、📌 集合地點、內文（交通路線框、提醒框、雨備框）、📍 開地圖、記帳區
- **分組行動的日子**：自動切成「A 組一區」「B 組一區」「全員會合一區」，各有彩色標題列與成員名單
- 最下方：💰 今日花費卡（預估每人、實際全團、平均每人、＋記其他花費、看全部花費）

**行程資料格式**（每段行程一筆）：
```js
{ k: 0,              // 固定編號（記帳靠它對應）。新增行程給一個新數字，不要改舊的
  t: "08:15", e: "09:00",  // 開始、結束（結束可省略；也可寫「上午」「下午」）
  meet: true,         // 是集合點才加
  where: "民宿門口",   // 集合地點
  group: "A",         // 分組行動才加
  title: "🚆 集合出發",
  place: "BTS Saphan Taksin",   // Google 地圖搜尋字（也可放經緯度 "13.71,100.51"）
  body: "<div class='route'>交通路線</div><div class='tip'>提醒</div><div class='rain'>雨備</div><img class='guide-img' src='img/xxx.webp'>" }
// 說明圖（例如機場接機位置圖）放在 site/img/，deploy.sh 會一起上傳；圖片下方註明來源
```

### 💰 花費（全團共用帳本）
- 總覽：全團總花費、平均每人、＋新增花費
- **公積金帳本**：總共收（每人 X 元 × 人數）、已花、剩餘（進度條：綠→橘→紅）、「現在結束每人可退 X 元」／「超支每人要補 X 元」、公積金花費明細、＋記一筆公積金花費
- 花費明細：可依天數篩選，**點任何一筆就能編輯**（可改天數、行程、金額、幣別、付款人、分給誰），內有刪除
- 💸 結算：**大家只跟一個結算人對帳**（公積金現金在他手上，已抵掉他墊的錢）。每人一行「誰 → 誰 多少」，點開看明細，右側可勾「已付款／已退款」（雲端共用）。詳見附錄 A-1
- 👥 每個人：先墊、應負擔、最終（補／退）
- 📊 錢花在哪：依標題關鍵字自動歸類，每類一行可展開；🧾 完整明細預設收合（附錄 A-2）
- **新增花費表單**：
  - 天數＋行程下拉選單（選了行程自動帶入名稱）
  - 金額＋幣別（**預設本國幣、放前面**；可切換當地幣）
  - 誰先付的（第一個選項是 💰 公積金）
  - 分給誰（預設全員；**分組行程預設只分給該組**；可全選／全不選）
  - 即時顯示「N 人，每人 X 元」
- **公積金分帳邏輯**：公積金支付視為全員平均出的錢；結算時公積金現金當成結算人已收到的錢，直接抵掉他墊的款，每人只剩一筆「補給／退給結算人」（附錄 A-1）
- 結算匯率是全團統一的固定值（寫在設定裡），不是每個人手機的匯率

### 🏨 住宿
1. 每間住宿一張卡（`PRIVATE.stays` 可放多間）：名稱、類型、哪幾晚、入住／退房時間、地址、📍 導航
2. **🛏️ 分房清單**（雲端共用）：
   - 每間房：床型、睡幾人（雙人床算 2、單人床算 1、沙發另計）、目前成員、人數（滿了變綠、超過變紅框）
   - 「還沒分房」名單（全部分好變綠色 ✅）
   - 編輯：點選誰住這間；已在別間的人會顯示（臥室 N），儲存後自動移過來
3. 🚕 給司機看：當地語言大字地址
4. 入住說明、🏠 住宿規定（安靜時段等）、🧳 退房前記得、📞 聯絡房東

### ☎️ 聯絡
- 重要聯絡人（領隊、房東、包車公司），一鍵撥號
- 分車名單（有包車時）
- 🆘 當地緊急電話：觀光警察、報警、救護、駐外辦事處急難救助、外交部旅外急難、旅平險急難救助
- 走散了怎麼辦（三步驟）

### ✅ 清單
- **出發前**順序：🛂 出發前準備（簽證／入境申報步驟卡、費用小卡、官方連結）→ 打包清單 → Dress Code 一覽 → 預約確認 → 匯率換算 → 實用外語 → 小撇步
- **出發當天起自動換順序**：匯率換算 → 實用外語 → 小撇步 → 其他 → 打包清單放最後

# 第四部分：內容整理原則（AI 收集資料時要遵守）

1. **不花錢**：優先用內建瀏覽器或使用者自己的 Chrome（已登入狀態）讀網頁，不用付費 API
2. **只摘要、不照抄**：用自己的話整理重點，每則**註明來源帳號**
3. **跳過重複**：已經在網頁上的店家不再新增，只在原卡片加「👍 朋友也推薦」
4. **跳過不適用的**：
   - 活動已結束或旅程前就截止的（期間限定、快閃）
   - **不能帶回國的東西**（例如肉製品），或在注意事項標紅字警告
   - 沒有店名或位置的（例如「留言才告訴你」）
   - 違法或不適合的內容
5. **事實要查證**：營業時間、搬家、入境規定等，以官方網站或最新資料為準；查不到要寫「出發前請再確認」，**不要猜**
6. **衝突先講**：新增內容如果跟行程打架（時間對不上、太遠、天氣），先提醒使用者再改
7. **不會的不亂寫**：不熟的店家只寫「朋友推薦，點地點看 Google 評價」
8. 輪播圖文貼文要一張一張翻完再整理；看不到的內容（需登入、被擋）照實說

# 第五部分：上線步驟

> 標 👤 的步驟要**使用者本人**操作，AI 做到這裡要停下來，說明使用者會看到什麼畫面、要按哪裡，等使用者說「好了」再繼續。

```bash
# 👤 1. 使用者自己註冊 Cloudflare（免費，不用綁卡）：https://dash.cloudflare.com/sign-up

# 👤 2. 登入：瀏覽器會跳出授權頁，確認網址是 dash.cloudflare.com 再按 Allow
npx wrangler login
npx wrangler whoami          # 確認：看到自己的 Email 就代表登入成功

# 3. 建立網站（名稱用隨機碼，避免被猜到）
npx wrangler pages project create <專案名-隨機碼> --production-branch main
#   ⚠️ 若出現「could not register workers.dev subdomain」，代表新版 Pages 會被導到 Workers，
#      改加 --force 建立舊版 Pages（只有建立這一次需要）

# 4. 建立資料庫，把 database_id 填進 wrangler.toml（第二部分 2-2 的 SQL 存成 schema.sql）
npx wrangler d1 create <資料庫名> --location apac
npx wrangler d1 execute <資料庫名> --remote --file schema.sql

# 👤 5. 設定留言板管理密碼 —— AI 先問使用者：「要自己設密碼，還是我幫你隨機產生一組？」
#    自己設（推薦）：AI 在使用者的終端機開 tools/set-password.sh（內容見下方），使用者自己輸入，會自動上傳並部署
tools/set-password.sh
#    隨機產生：AI 產生隨機碼存進 admin.key（加進 .gitignore，不要上傳），請使用者自己打開檔案複製，不要貼在對話裡
printf '%s' "$(cat admin.key)" | npx wrangler pages secret put ADMIN_KEY --project-name <專案名>
#    ⚠️ 密碼要「重新部署後」才會生效，設完記得跑下一步

# 6. 上傳（之後每次修改都只要跑這行）
./deploy.sh
```

**`tools/set-password.sh`**（讓使用者自己在終端機設定管理密碼，密碼不會出現在 AI 對話裡；AI 照抄存檔後 `chmod +x tools/set-password.sh`，再請使用者執行）
```bash
#!/bin/bash
# 設定／更改留言板管理密碼：密碼只在這個終端機輸入，不會出現在對話裡
# 改完會自動重新部署；舊密碼登入的手機會全部被登出
set -e
SRC="$(cd "$(dirname "$0")/.." && pwd)"
PROJECT="$(grep -E '^name *=' "$SRC/wrangler.toml" | cut -d'"' -f2)"
echo "🔐 設定「${PROJECT}」的留言板管理密碼（輸入時畫面不會顯示字，這是正常的）"
while true; do
  read -r -s -p "新密碼（至少 8 個字）：" P1; echo
  read -r -s -p "再輸入一次：" P2; echo
  if [ "$P1" != "$P2" ]; then echo "❌ 兩次不一樣，再來一次"; continue; fi
  if [ ${#P1} -lt 8 ]; then echo "❌ 太短了，至少 8 個字"; continue; fi
  break
done
printf '%s' "$P1" > "$SRC/admin.key"; chmod 600 "$SRC/admin.key"
printf 'ADMIN_KEY=%s\n' "$P1" > "$SRC/.dev.vars"
printf '%s' "$P1" | npx wrangler pages secret put ADMIN_KEY --project-name "$PROJECT" >/dev/null
echo "✅ 密碼已更新，正在重新部署讓新密碼生效…"
"$SRC/deploy.sh" >/dev/null 2>&1 && echo "🎉 完成！請用新密碼登入。" || echo "⚠️ 部署失敗，請跟 Claude 說"
```

**wrangler.toml 範本**
```toml
name = "<專案名-隨機碼>"
pages_build_output_dir = "./site"
compatibility_date = "2026-09-01"

[[d1_databases]]
binding = "DB"
database_name = "<資料庫名>"
database_id = "<步驟 4 拿到的 ID>"
```

**deploy.sh**（複製到乾淨暫存資料夾再上傳，避免把多餘檔案傳上去）
```bash
#!/bin/bash
set -e
SRC="$(cd "$(dirname "$0")" && pwd)"; TMP="$(mktemp -d)"; mkdir -p "$TMP/site"
cp "$SRC/wrangler.toml" "$TMP/"; cp -R "$SRC/functions" "$TMP/"
cp "$SRC/site/index.html" "$SRC/site/_headers" "$SRC/site/robots.txt" "$TMP/site/"
[ -d "$SRC/site/img" ] && cp -R "$SRC/site/img" "$TMP/site/"
cd "$TMP" && npx wrangler pages deploy --branch main --commit-dirty=true
```

| 個別提醒（**本人同意後**） | 管理密碼、API 金鑰 |

- 記帳、推薦、分房「拿到網址的人都能改」（朋友互信設計）；擔心誤刪可改成需要管理密碼
- 所有使用者輸入都要跳脫，避免被貼惡意程式碼

# 第八部分：踩過的坑（直接避開）

1. **行程編號 `k` 要固定**：用陣列順序對應記帳的話，插入新行程會讓舊帳對錯行程
2. **打包清單新項目只能加在最後**：勾選是照順序存的
3. **localStorage 一定要 try/catch**：私密瀏覽或被封鎖時會出錯
4. **重新整理畫面時保留使用者展開的卡片**，不然記完帳卡片就收起來了
5. **換算器、表單輸入中不要整頁重畫**，只更新需要的部分
6. **文字比對要小心包含關係**：例如 ICONSIAM 會被當成 SIAM，要排除
7. **wrangler 在某資料夾執行 login 可能自動產生 `wrangler.jsonc`**，從那個資料夾部署會失敗 → 用 deploy.sh 從乾淨資料夾上傳
8. **Cloudflare 會擋 Python 預設 User-Agent**，用 curl 呼叫 API
9. **Instagram 內嵌要有網路**才看得到；Klook 等網站可能跳機器人驗證（不能代為通過，請使用者自己開）
10. **店家營業時間、市集搬家、入境規定常變**：出發前一週再確認一次

| `Authentication error [code: 10000]`、`Not logged in` | Cloudflare 登入過期了（大約一個月） | 👤 `npx wrangler login`，重新按 Allow |

# 附錄：曼谷實戰後新增的功能與做法（2026-10，v2）

> 曼谷團出發前後陸續加上的功能。A-1～A-3、A-6 已內建在 `assets/group/index.html`；A-4 的領隊整理、退稅表、貴賓室和 A-5 的路線圖、鑰匙盒是**目的地專屬的選配**，需要時請 AI 照描述加。標 ⚙️ 的是要改設定／資料才會生效的地方。

## A-1 結算改成「所有人只跟一個人對帳」（取代最少轉帳配對）

朋友團實測：最少轉帳演算法會出現「A 付 B 零頭」這種對不上真實帳的配對，團員會困惑。改成：

- ⚙️ `SETTLER`（結算中心，通常是領隊／會計）。公積金現金在這個人手上，視為他已經收到的錢。
- 每人最終 ＝ `繳的公積金 − 應分攤的全部花費（公積金付的＋個人墊的）＋ 自己先墊的`。正數＝結算人退給他，負數＝他補給結算人。結算人自己不列轉帳。
- 檢查式：全員最終加總 ＝ `公積金總額 − 公積金已付`。部署前用真實資料在 Node 跑一次驗證。
- 畫面：「結算：大家只跟 X 對帳」每人一行；底下「X 會收到／要退出去」合計。
- **每一行可展開明細**（`<details class="mv">`）：＋繳公積金；－應分攤的每一筆（名稱、誰付的、幾人分、金額，大到小）；＋自己先墊的；最後一行「X 退給 N／N 補給 X」。展開狀態重新整理時要保留。
- **已付款／已退款確認**（雲端共用，任何人可勾）：每行右側 `paidbtn`，按一次勾、再按取消。勾選時存當時的金額，之後金額變了就顯示「⚠️ 金額變了」。API `/api/settle`（GET 全部、POST `{name, amount, dir, paid}`）、資料表 `settle_paid`（見 2-2）。按鈕在 `<summary>` 裡，點擊處理要 `preventDefault + stopPropagation`，否則會誤展開明細。
- 「每個人」表欄位：先墊／應負擔／最終（含公積金）。
- 若有人先墊了「全團共用」的小額（例如車票），**記成公積金付款**，結算人現金退給他；不要記成個人墊付，否則會被拆成零頭。⚠️ 同一筆不要記兩次（曾經公積金版和個人版同時存在，重複計算）。

## A-2 花費頁版面（54 筆也讀得下去）

由上到下：總覽 → 公積金帳本 → 結算（含明細、確認勾選）→ 每個人 → **📊 錢花在哪（自動歸類）** → **🧾 完整花費明細（預設收合，點開才有天數篩選與編輯）**。

- 自動歸類 `CATS`：依「標題關鍵字」比對，**順序很重要**（先交通，再體驗、餐飲、購物；例如「移動到某餐廳晚餐」要先被判成交通）。分類：🏨住宿、🛡️保險、🚕交通、🎟️體驗・行程、🍜餐飲、🛍️購物・藥品、📦其他。上線前拿真實資料逐筆檢查有沒有歸錯，並提醒使用者「歸錯就改標題」。
- 不要合併或刪除原始花費；只改呈現。

## A-3 行程頁

- **天數輪轉**：每過一天，當天排第一個，已過的天數接到最後面（Day 編號不變、記帳不受影響）。
- **首頁航班**：去程日過後（例如抵達日 00:00 起）只顯示回程班機。
- **只限部分人的行程**：行程項目加 `only:["甲","乙"]`，會獨立成一個「🍽️ 晚餐（甲、乙）」區段，並在內文顯示「參加：…」。分組日（有 `groups`）也適用，避免被歸到「全員」。
- **選一選的晚上**：用 `.opt` 卡片列出 N 個方案，標題寫「晚上行程 N 選 1（討論中）」，決定後再改成單一行程。取消方案時要重新編號、改標題、清掉「在哪買」之類引用該方案的標籤。
- **🥚 蛋奶素可參考**（每個景點項目底下可展開）：資料放在 `VEG`（區域→店家：名稱、類型 全素／素食菜單／可調整、說明）與 `VEG_MAP`（[第幾天, 行程 k, 區域]）。區域沒有查到店就誠實寫「查不到」，改放建議（請包車司機先講、泰文點餐句、備乾糧）。⚙️ 新旅程若有素食者才加；沒有就整段拿掉。展開狀態要在重畫時保留（`data-vk`）。
- 巢狀 `<details>` 會吃到外層 `.item details` 的白底／色條／陰影，**要用 `.item details.veg` 之類更具體的選擇器蓋回去**。

## A-4 清單頁

- 順序（出發前）：入境須知 → 領隊整理 → 打包清單 → Dress Code → 預約確認 → 時差 → 換算 → 小撇步 → 退稅 → 貴賓室 → 外語。**出發當天起，前五項移到最下面**。
- **📖 領隊整理：行前必讀**：可收合的大卡，內含出發前行動事項、出發日、天氣與健康、交通、換錢與消費、購物、便利商店、飲料、行程重點、按摩、素食、緊急聯絡。與入境須知／退稅／貴賓室重複的只放重點並指過去。
- **🧾 退稅（含級距表）**：不要寫「退 7%」。泰國 VAT 7%，實際依官方級距表退（2,000 泰銖起；2,000–19,999 約只退 3–5%；200,000 以上才是 6.1%）。表格用程式產生（`vatRows()`，79 列），**資料來自泰國稅務局官方圖片（2013/9 起適用）**——官網與部落格的表都是圖片，文字抓不到，要把圖片轉成 PNG 用眼睛讀，並逐格核對。另含湊級距提醒、機場 2 萬泰銖分界流程、高價品二次查驗（手提）、領款方式、市區退稅。
- ⚙️ 其他國家的退稅／貴賓室內容不通用，換目的地要重新查。

## A-5 民宿頁

- 「🗺️ 怎麼走到民宿」：放房東提供的路線指引圖（`img/` 底下，`loading="lazy"`、有 alt）。
- 「🔑 鑰匙盒怎麼開」：圖文三步驟。**密碼預設不放網頁**；只有屋主／領隊**明確決定**才放（放了就加 📋 一鍵複製，並提醒「網址任何人拿到都能看，退房後請房東換密碼」）。⚙️ 沒有房東圖片就整段拿掉。

## A-6 其他小功能

- 旅程結束卡（出發日期過後）：可放「上傳照片／下載照片」兩個大按鈕（相簿連結由使用者提供）。
- 公積金金額改了要同步改「領隊整理」的行動事項文字。
- 旅程名稱用字要請使用者確認一次（曾把團名打錯一個字，整個網站、模板都得重改）。

## A-7 合作規則（給 AI）

1. **不確定要放哪個分類／頁面、查不到的資料（樓層、價格、營業時間）、來源互相衝突時，先停下來問使用者，不要自己判斷**（曾把逛街地圖的店放錯到伴手禮推薦）。
2. 收集資料不花 API 費用：讀 IG 貼文用 `https://www.instagram.com/reel/<代碼>/embed/captioned/` 的公開嵌入頁；有帳號限制的貼文請使用者貼文字或截圖。
3. 每次改版：語法檢查 → `?now=` 模擬 → 手機寬度 → 部署 → 在**正式網址**確認（`curl` 加 `Cache-Control: no-cache`，新部署有幾秒延遲）。
4. 要刪或改使用者的資料（花費、推薦）前先說明，確認後才動；改完回報影響到誰、多少錢。

## A-8 踩過的坑（v2 新增）

- 結算要「真實」：配對式最少轉帳會產生非真實的零頭轉帳；改成單一結算人最直觀。
- 同一筆共用花費被記兩次（公積金版＋個人版）會讓全員多付；結算前檢查標題相近、金額相同的項目。
- macOS 的 `sed -i` 要 `sed -i ''`；改檔一律用 Python 並加 `assert count == 1`。
- 在 `<summary>` 裡放按鈕，點擊要攔截預設行為，否則按鈕會同時展開／收合外層。
- 新增資料表要用 `npx wrangler d1 execute <資料庫名> --remote --command "CREATE TABLE IF NOT EXISTS …"`，新 API 檔放 `functions/api/` 再部署。
- 本機預覽沒有 `/api`，要測畫面時把真實資料存成暫時的 JSON 檔放 `site/`，測完刪掉（`deploy.sh` 只複製指定檔案，不會上傳它）。
